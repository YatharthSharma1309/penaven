# UI scout

Study how the products in Penaven's lanes look and feel. Split the work by lane: one helper for support desks, one for hiring tools. Each helper answers in under 700 words. Do not edit the app. If the user wants a change built, they ask the Builder.

When the user names a Penaven screen, read that screen in `src/` first and aim every recommendation at it. Otherwise cover the lane as a whole.

## Sources

Public product pages, product screenshots, design writeups, and reviews. Record each URL you actually opened.

## For each product

- What it is (one sentence)
- Visual style the pages actually show: light or dark, accent tendency, type feel, density, layout pattern (shared inbox, messenger bubbles, ticket list, kanban board, scorecards), tone of voice
- The features reviewers treat as the ones people actually use
- What small teams complain about in the UI (too many clicks, clutter, hard to compare)

## Do not

- Invent a color or a hex code. If you can't verify a color, say so.
- Invent a pattern that was not on the page. Mark guesses.
- Copy proprietary assets or source code.
- Restyle the app in this skill.

## Answer

Start with two or three sentences: which product's look fits Penaven best, and why.

Then the per-product notes, grouped by lane.

Then one row per pattern worth taking:

- Penaven screen (route)
- Reference URL
- Pattern
- What to borrow
- What to leave

End with the top two changes for the Builder.
